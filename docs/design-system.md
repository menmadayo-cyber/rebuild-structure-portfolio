# デザインシステム｜Rebuild Structure

本サイトの見た目（色・タイポグラフィ・余白・コンポーネント等）のルール定義。色は初期値（トークン名＋参考カラーコード）として示している。

---

## 1. 色の役割

白を基調に、濃紺・青系を主色とする。清潔感・信頼感を保ちつつ、「相談しやすさ」を損なわない明るさを残す。ネオン・彩度の高いグラデーション・宇宙／ロボット的な配色は使わない。

| 役割 | トークン名 | 参考カラー | 用途 |
|---|---|---|---|
| 背景（基本） | `bg-base` | `#FFFFFF` | ページ全体のベース背景 |
| 背景（セクション区切り用） | `bg-subtle` | `#F4F6FA`（白に近い薄紺グレー） | セクションの交互背景、カード内の入れ子背景 |
| 背景（反転・強調） | `bg-inverse` | `#0F2647`（濃紺） | お問い合わせセクション、フッターなど着地点の強調背景 |
| 本文 | `text-body` | `#1E2A3A`（黒に近いネイビーグレー） | 本文テキスト。純黒は使わず、目に柔らかい濃色にする |
| 見出し | `text-heading` | `#0F2647`（濃紺） | H1〜H3見出し。本文よりやや濃く、主色と統一 |
| 補助テキスト・注釈 | `text-muted` | `#5B6B80` | 補足説明、日時、プレースホルダー注記など |
| 反転背景上のテキスト | `text-on-inverse` | `#FFFFFF` / `#D7E0EC` | `bg-inverse` の上で使う本文・見出し |
| 主色（濃紺） | `color-primary` | `#0F2647` | ヘッダー、主要見出しのアクセント、プライマリボタン背景 |
| アクセント（青） | `color-accent` | `#2E6FEC`（中間的な明るい青） | リンク、セカンダリボタン枠線、アイコン、ホバー状態 |
| 罫線・区切り線 | `color-border` | `#E1E6EE` | カード枠線、表の罫線、セクション内の区切り |
| 成功表示 | `color-success` | `#2F8F5B`（落ち着いたグリーン） | 「実施実績あり」等の肯定的なタグ |
| 注意・留意表示 | `color-notice` | `#B5762A`（落ち着いたアンバー） | 「ダミーデータ使用」「準備中」等の留意タグ・注記ボックス |

**運用ルール**
- 1画面内で使う彩度の高い色は `color-accent` の1色に限定し、それ以外は無彩色〜低彩度の紺系でまとめる。
- `color-success` / `color-notice` はタグや注記など「情報の性質を伝える」用途のみに使い、装飾目的では使わない。
- グラデーションを使う場合は `bg-base → bg-subtle` など近似色同士の弱いグラデーションに限定し、コントラストの強い多色グラデーションは使わない。

## 2. フォント方針（日本語の読みやすさ優先）

- 装飾的・視認性の低い書体は使わず、可読性の高いゴシック体を基本とする。
- Webフォントを新たに読み込むよりも、まずOSに搭載された高品質な日本語ゴシックを優先するシステムフォントスタックとする（表示速度・読み込み負荷を抑える方針とも合致）。
- 想定スタック（実装時の参考）：`"Hiragino Kaku Gothic ProN", "Hiragino Sans", "Yu Gothic", "Meiryo", -apple-system, "Segoe UI", sans-serif`
- 和文と英数字が混在する見出し・本文が多いため、和欧混植で不自然な字間にならないフォントの組み合わせを優先する。
- 本文の行間（line-height）は日本語の可読性を優先し、余裕を持たせる（目安：本文1.8、見出し1.4〜1.5）。
- 見出しの字間（letter-spacing）はごくわずかに広げ、圧迫感を減らす（目安：0.02em程度）。
- 太字は多用せず、見出し・強調語・ボタン文言など役割を絞って使用する。

## 3. 見出し・本文・注釈の文字サイズ

モバイルファーストの目安（実装時にpx／remへ変換）。

| 用途 | モバイル | デスクトップ | 備考 |
|---|---|---|---|
| H1（ファーストビュー見出し） | 28〜32px | 44〜52px | 2〜3行で折り返す前提の文字量 |
| H2（セクション見出し） | 22〜24px | 30〜34px | 全セクション共通 |
| H3（カード見出し） | 17〜18px | 19〜20px | サービス・事例・FAQ等のカード見出し |
| 本文 | 15〜16px | 16px | 行間1.8を基本とする |
| リード文（セクション導入） | 15〜16px | 17〜18px | 本文よりわずかに大きく、導入であることを示す |
| 補助・注釈（プレースホルダー表記、注意事項等） | 13px | 13〜14px | `text-muted` を使用 |
| ボタン文言 | 15px | 15〜16px | 本文と同等、太字寄り |
| タグ・バッジ | 12〜13px | 12〜13px | 全セクション共通の最小サイズ |

## 4. 最大コンテンツ幅

| 要素 | 最大幅の目安 |
|---|---|
| 通常セクション（カードグリッド等） | 1140px |
| ヒーロー・お問い合わせ等の中央寄せテキストブロック | 720〜760px（可読行長を優先） |
| 実績詳細ページの本文 | 680〜720px（記事として読みやすい行長） |
| ヘッダー内コンテンツ | 通常セクションと同じ1140px |

いずれも左右に最低16px（モバイル）〜48px（デスクトップ）のサイド余白を確保し、画面端に文字が接しないようにする。

## 5. 余白の基準

8pxを基準としたスペーシングスケールを使用し、セクション間・カード内・要素間で一貫させる。

| トークン | 値 | 主な用途 |
|---|---|---|
| `space-1` | 4px | アイコンとテキストの間隔など最小単位 |
| `space-2` | 8px | タグ内パディング、インライン要素の間隔 |
| `space-3` | 16px | カード内の要素間、フォーム要素の間隔 |
| `space-4` | 24px | カード内パディング、カード間ギャップ（モバイル） |
| `space-5` | 32px | カード間ギャップ（デスクトップ）、見出しと本文の間隔 |
| `space-6` | 48px | セクション内の大ブロック間隔 |
| `space-7` | 64px | セクション上下パディング（モバイル） |
| `space-8` | 96px | セクション上下パディング（デスクトップ・標準） |
| `space-9` | 120〜160px | ファーストビュー／お問い合わせ等、余白を強調したいセクション |

各セクションの余白は、このスケールの値を組み合わせて構成する。

## 6. カード・ボタン・タグ・表・FAQの見た目

### カード
- 背景：`bg-base`（白）。セクション背景が `bg-subtle` の場合はカードを白のまま残し、コントラストで浮かせる。
- 枠線：`color-border` の1px罫線を基本とし、影は使わないか、ごく弱い影のみを補助的に使う（6章参照）。
- 角丸：`radius-md`（12px）。
- 内側パディング：`space-4`（モバイル）〜`space-5`（デスクトップ）。
- 主力カード（AI秘書アプリなど強調カード）は、枠線を `color-accent` に変更するか、内側パディングを一段階広げることで差別化する（色数を増やさない）。

### ボタン
- プライマリボタン：背景 `color-primary`、文字 `text-on-inverse`（白）。主要な行動喚起（相談する、フォームへ 等）に使用。
- セカンダリボタン：背景透明、枠線 `color-accent` または `color-primary`、文字は同色。補助的な行動喚起に使用。
- 角丸：`radius-sm`（8px）。ピル型（全周丸め）は使わず、清潔感のある四角み寄りの形にする。
- パディング目安：上下12〜14px、左右24〜28px。
- 1セクション内でプライマリは1つまでとし、複数ボタンがある場合は残りをセカンダリにする（優先度を視覚的に一つに絞る）。

### タグ・バッジ
- 形状：角丸4〜6px（カードより控えめな丸み）の小さな矩形。
- 背景は低彩度（`bg-subtle` またはそれに準じる薄色）、文字色で意味を区別する。
  - 実施実績あり／確定情報：`color-success` を文字色または背景に薄く使用。
  - ダミーデータ使用／自主制作デモ／準備中：`color-notice` を文字色または背景に薄く使用。
  - 中立的な分類（自主制作、主力作品等）：`text-muted` ベースの無彩色。
- タグは色だけで意味を伝えず、必ずテキストを併記する（アクセシビリティ方針3.参照）。

### 表（参考料金・仕様等）
- ヘッダー行：背景 `bg-subtle`、文字 `text-heading`、太字。
- 罫線：`color-border` の細い横罫線のみ（縦罫線は使わないか最小限にし、圧迫感を減らす）。
- 行の高さに余裕を持たせ（`space-3`〜`space-4` のセル内パディング）、数値や短い語句が詰まって見えないようにする。
- 交互背景（ゼブラストライプ）は使う場合も `bg-subtle` のごく薄い差にとどめる。

### FAQ（アコーディオン）
- リスト形式、各項目は `color-border` の下線区切り（カード化はしない）。
- 質問行：太字、右端に開閉アイコン（＋／−、または▸／▾）。
- 回答部分：質問より若干インデント、`text-body` で表示。
- 開閉の状態変化は色や太さを大きく変えず、アイコンの向き変化とわずかな背景色変化（`bg-subtle`）程度に留める。

## 7. 角丸・影・ホバー表現

| トークン | 値 | 用途 |
|---|---|---|
| `radius-sm` | 8px | ボタン、タグに準じる小要素 |
| `radius-md` | 12px | カード全般 |
| `radius-lg` | 16〜20px | ヒーロー背景ブロック、フィーチャーカード等、際立たせたい大きな面 |

- 影は「ごく弱い影1種類」のみを基本とし、複数の強さを併用しない（例：`box-shadow: 0 2px 8px rgba(15, 38, 71, 0.06)` 相当の弱いもの）。
- 影よりも罫線（`color-border`）による区切りを優先し、影は「浮いている」ことを示す補助として最小限に使う。
- ホバー表現は次の3種類に限定する。
  1. カード：枠線の色を `color-border` → `color-accent` に変化、影をごくわずかに強める。
  2. ボタン：背景色をわずかに濃く／薄くする（プライマリは暗く、セカンダリは薄く塗りつぶす）。
  3. テキストリンク：下線の表示、または文字色を `color-accent` に変化。
- 拡大・回転・パララックス・自動再生アニメーション等、動きの大きい表現は使わない。状態変化のトランジションは150〜200ms程度の短いフェード／色変化に限定する。

## 8. スマートフォンのブレークポイント方針

モバイルファーストで設計し、画面幅が広がるごとにグリッド列数を増やす。

| ブレークポイント名 | 目安の幅 | 主な変化 |
|---|---|---|
| base（モバイル） | 〜767px | 1カラム。ヘッダーはハンバーガーメニュー化。カードはすべて縦積み。 |
| tablet | 768px〜1023px | 2カラムグリッドを許容（例：料金カード2×2、事例カード2件並びなど）。ヘッダーのアンカーリンクは折り返しつつ表示、または引き続きハンバーガー。 |
| desktop | 1024px〜1279px | 3カラムグリッドを許容（サービス、研修セクション等）。ヘッダーのアンカーリンクを全項目横並び表示。 |
| wide | 1280px〜 | レイアウトはdesktopと同じ。最大コンテンツ幅（4章）を超えて広がらないよう中央寄せを維持する。 |

- グリッド列数の切り替えは「1→2→3」の順に段階を踏み、tabletを飛ばして1→3に一気に変化させない（表示崩れ・読みにくさの防止）。
- ヒーローや実績詳細ページの本文幅は、wideになっても4章で定義した最大幅を超えて広げない。

## 9. アクセシビリティ方針

- **コントラスト**：本文と背景のコントラスト比はWCAG AA基準（通常文字4.5:1以上、大きい見出し等3:1以上）を満たす配色を基本とする。`text-muted` を背景色に対して使う際は特に確認する。
- **色だけに依存しない**：タグや成功・注意表示は色だけでなくテキストラベルを必ず併記する（例：色付きバッジ＋「ダミーデータ使用」の文言）。
- **見出し構造**：ページごとにH1は1つのみとし、セクション見出し（H2）→カード見出し（H3）の階層を意味的に正しく使う。装飾目的で見出しレベルを飛ばさない。
- **フォーカス表示**：キーボード操作時、リンク・ボタン・アコーディオン・ハンバーガーメニューにフォーカスリング（枠線）を明示する。`outline: none` で消さない。
- **タップ領域**：ボタン・リンク・アコーディオン見出し等の操作領域は、モバイルで最低44×44px相当を確保する。
- **代替テキスト**：装飾用の抽象パターン・アイコンには意味のある代替テキストを付けない（空alt）が、情報を持つ画像（プロフィールのアイコン枠、事例のスクリーンショット等を将来追加する場合）には内容を説明するaltを付与する。
- **動きへの配慮**：`prefers-reduced-motion` を尊重し、ユーザーがOS側でアニメーション低減を設定している場合は、ホバー・開閉トランジションを最小限（またはなし）にする。
- **フォーム・問い合わせ導線**：将来的にフォームを実装する際は、各入力欄にラベルを明示し、プレースホルダーのみをラベル代わりにしない。
- **言語・文章**：`lang="ja"` を明示し、専門用語には言い換えを添える方針を、視覚的にも（注釈テキストやツールチップ等）補強する。

## 10. デザイン方向性との対応チェック

| 方針（ユーザー指定） | 本ドキュメントでの対応 |
|---|---|
| 白基調、濃紺・青系を主色 | `bg-base`＝白、`color-primary`＝濃紺、`color-accent`＝青の1色構成（1章） |
| 清潔感・信頼感・相談しやすさ | 低彩度パレット＋余白多め（5章）、着地点となるお問い合わせセクションのみ反転背景で導線を明確化 |
| 過度なネオン・宇宙・ロボット表現を避ける | 彩度の高い色・多色グラデーション・装飾的書体を使わない方針を明記（1章・2章） |
| 写真がなくても成立する構成 | カード＋タグ＋テキストを中心とした構成とし、画像は装飾的パターンに限定 |
| 過剰なアニメーションを使用しない | ホバー・開閉表現を3種類・短いトランジションに限定（7章） |
| 参考サイトの見た目を再現しない | 具体的な参考サイト名・デザインを引用せず、色・余白・形状をトークンとして抽象化して定義 |
